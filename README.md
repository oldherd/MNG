# MNG: An Efficient Graph-Based Index for Multi-Vector Similarity Search

This repository contains the implementation of **MNG**, a native graph index for multi-vector similarity search (MVSS), together with baseline implementations and data preparation tools.

**[Online full paper](fullpaper.pdf)** · **[Run MNG](#compile-and-run-mng)** · **[Run baselines](docs/reproduction.md#build-options-and-baselines)**

## Abstract

Multi-vector similarity search has emerged as a powerful paradigm for fine-grained semantic retrieval, offering richer representations than traditional single-vector methods. However, existing solutions rely on a filter-and-refine framework built upon single-vector indexes, which often treat the token vectors within each multi-vector in isolation and overlook their correlations. This leads to an inherent dilemma: aggressive filtering sacrifices recall, while conservative filtering incurs prohibitive computational cost. The root cause is the lack of native multi-vector indexing support in existing solutions.

To address this, we propose MNG, a native graph index for multi-vector similarity search. MNG introduces a symmetric, cardinality-normalized edge weight that makes multi-vector similarity suitable for proximity graph construction, a routing-guided index construction algorithm that reduces candidate evaluations, and an accelerated multi-vector similarity computation algorithm. Extensive experiments on six real-world datasets demonstrate that MNG significantly outperforms state-of-the-art solutions, achieving up to 13.0× speedup while maintaining over 90% recall.

## Datasets

We use the five **LoTTE test collections** (Lifestyle, Recreation, Writing, Science, and Technology) and the **MS MARCO passage collection**, with 128-dimensional token vectors generated by ColBERTv2.

- **LoTTE:** use the dataset instructions in the [official ColBERT repository](https://github.com/stanford-futuredata/ColBERT/blob/main/LoTTE.md).
- **MS MARCO:** use the passage collection and passage-dev queries from the [official dataset repository](https://github.com/microsoft/MSMARCO-Passage-Ranking).
- **Encoder:** obtain the ColBERTv2 code and checkpoint through the [official ColBERT repository](https://github.com/stanford-futuredata/ColBERT).

The source repository contains encoding and ground-truth tools; corpora, checkpoints, precomputed embeddings, and indexes are downloaded or generated separately. See [Prepare the data](#prepare-the-data) for encoding instructions and the TSV and multi-vector bundle formats. For MS MARCO, the paper uses 500 queries sampled without replacement with seed 42 from the 6,980 passage-dev queries; the selected query-ID list is not included in this repository.

## Environment

The experiments in the paper used GCC 9.2.1 with `-O3`, Python 3.8.20, and Alibaba Group Enterprise Linux Server 7.2 on a server with two Intel Xeon Platinum 8163 CPUs at 2.50 GHz and 512 GB RAM. Index construction used 96 threads; similarity search was single-threaded.

To build and run MNG, prepare:

- Linux, GNU Make, and a C++17 compiler with OpenMP support.
- The C++ [FAISS library](https://github.com/facebookresearch/faiss/blob/main/INSTALL.md) and Intel MKL, including their development headers. The default link configuration uses MKL-backed FAISS; the MNG searcher also uses MKL directly for exact MaxSim reranking.
- For data preparation: Python, NumPy, PyTorch, and ColBERTv2. The encoder requires a CUDA-capable GPU. Install the Python dependencies according to the ColBERT version you use.

MNG build settings are described in [Build options](#build-options). For baseline dependencies and execution instructions, see the [baseline guide](docs/reproduction.md#build-options-and-baselines).

## Compile and run MNG

The following steps cover data preparation, index construction, and similarity search with MNG. After cloning the repository, run the commands from its root directory and replace `/path/to/...` with your local paths.

[Build MNG](#build-mng) · [Prepare the data](#prepare-the-data) · [Build an index](#build-an-index) · [Run similarity search](#run-similarity-search) · [Parameters](#parameters) · [Output and evaluation](#output-and-evaluation) · [Build options](#build-options)

### Build MNG

Clone the repository and build the MNG binaries. Replace the library paths with your installation prefixes:

```bash
git clone https://github.com/oldherd/MNG.git
cd MNG

make -j8 mng \
  FAISS_ROOT=/path/to/faiss \
  MKL_ROOT=/path/to/mkl \
  MNG_INDEX_THREADS=96 \
  MNG_BACKEND=auto
```

This creates `mng/build/indexer_mng_exp` and `mng/build/searcher_mng_exp`. `MNG_INDEX_THREADS` is a build-time setting; choose a value suitable for your machine. After changing build flags, rebuild from clean objects as described in [Build options](#build-options).

### Prepare the data

Download the LoTTE test collections and MS MARCO passage data through the links in [Datasets](#datasets). Obtain the ColBERTv2 checkpoint and install the dependencies of the [official ColBERT implementation](https://github.com/stanford-futuredata/ColBERT). The encoding script imports `colbert`, NumPy, and PyTorch and calls CUDA directly.

Prepare separate document and query TSV files, with one integer ID and one text field per line:

```text
0<TAB>First document or query text
1<TAB>Second document or query text
```

Here `<TAB>` denotes a literal tab. Keep a stable row order through encoding, index construction, ground-truth generation, and evaluation. For MS MARCO, the exact 500-query ID list used for the paper is not included; matching a random seed alone does not specify the sampling implementation or source ordering.

#### Encode documents and queries

```bash
python encoders-v2/encode.py \
  --mode doc \
  --input /path/to/collection.tsv \
  --output data/docs.mvbundle \
  --ckpt /path/to/colbertv2-checkpoint \
  --vanilla /path/to/ColBERT \
  --dim 128 --doc_maxlen 220 --batch_size 64

python encoders-v2/encode.py \
  --mode query \
  --input /path/to/queries.tsv \
  --output data/queries.mvbundle \
  --ckpt /path/to/colbertv2-checkpoint \
  --vanilla /path/to/ColBERT \
  --dim 128 --query_maxlen 32 --batch_size 64 \
  --keep_padding
```

These are the encoder's default dimension and length settings, made explicit. `--vanilla` adds an existing ColBERT checkout to the Python import path; it can be omitted if `colbert` is already installed. `--dim` records the output dimension and must match the checkpoint. It does not retrain or resize its projection layer. Use `--limit N` for an initial small encoding run.

**Keep `--keep_padding` for queries:** the ground-truth generator requires fixed-length query bundles. The document bundle stores FP16 token vectors, while the query bundle stores FP32 token vectors.

```text
data/docs.mvbundle/          data/queries.mvbundle/
  embeddings.fp16.bin         embeddings.fp32.bin
  doclens.i32.bin             doclens.i32.bin
  docids.i32.bin              docids.i32.bin
  meta.json                  meta.json
```

`doclens.i32.bin` records the token count of each row. `docids.i32.bin` records its original input ID. Token vectors are concatenated in row order. MNG requires a document bundle with `is_query=false`, a query bundle with `is_query=true`, matching vector dimensions, and nonempty objects. The original document bundle is also required at search time.

Verify a generated bundle with the supplied reader:

```bash
python encoders-v2/mvbundle.py data/docs.mvbundle --verify
python encoders-v2/mvbundle.py data/queries.mvbundle --verify
```

#### Generate MaxSim ground truth

```bash
python encoders-v2/compute_topk.py \
  --doc_bundle data/docs.mvbundle \
  --query_bundle data/queries.mvbundle \
  --output data/groundtruth.gt \
  --top_k 1000 --gpu 0
```

This enumerates query-document pairs using MaxSim. Token dot products use FP16 arithmetic and the final aggregation uses FP32. The output includes the full `scores.fp32.bin` matrix, `topk_indices.i32.bin`, `topk_scores.fp32.bin`, and `meta.json`. The full score matrix requires approximately `4 × number_of_queries × number_of_documents` bytes, in addition to the top-k files. Set `--top_k` at least as large as the largest search `--k` you intend to evaluate.

For GPU memory control, add `--doc_chunk_tok N` to process document tokens in chunks. A small numerical check is available with `--smoke`; add `--device cpu` to run that check without CUDA. Normal full ground-truth generation uses CUDA.

Ground truth must correspond to the same document and query bundles, including their row order and query count. The searcher does not align ground-truth rows by original query IDs. When using `--query_start` / `--query_stop`, prepare the matching query subset for evaluation as well.

### Build an index

Once the document and query bundles have been prepared, build an index:

```bash
mkdir -p indexes results

./mng/build/indexer_mng_exp \
  --doc data/docs.mvbundle \
  --index_dir indexes/mng \
  --param M=32 --param M0=64 \
  --param assignment_gamma=64 --param anchor_ratio=32 \
  --param ef_nav_build=128 --param ef_nav_assign=128 \
  --param seed=42
```

### Run similarity search

Search the query bundle and evaluate against the matching ground truth:

```bash
./mng/build/searcher_mng_exp \
  --doc data/docs.mvbundle \
  --query data/queries.mvbundle \
  --gt data/groundtruth.gt \
  --index_dir indexes/mng \
  --k 100 \
  --param ef_nav_query=128 \
  --param ef_search=256 \
  --param rerank_amp=2.64 \
  --output results/mng.json
```

These commands illustrate the workflow; experiment settings vary by evaluation. Omit `--gt` to search without ground-truth evaluation. See [Parameters](#parameters) and [Output and evaluation](#output-and-evaluation) for configuration and result details.

### Parameters

The parameter defaults below are taken from the argument parsers, rather than the example values in the usage message:

| Option | Code default | Meaning |
| --- | --- | --- |
| `--param M` | `32` | Routing Graph degree parameter |
| `--param M0` | `2*M` | Traversal Graph degree parameter |
| `--param assignment_gamma` | `M0` | Number of routing assignments used to gather construction candidates |
| `--param anchor_ratio` | `M` | Controls the size of the sampled routing subset |
| `--param ef_nav_build` | `128` | Routing Graph construction beam width |
| `--param ef_nav_assign` | `128` | Beam width for routing assignments during construction |
| `--param seed` | `42` | Construction random seed |
| `--param kmeans_niter` / `kmeans_nredo` | `25` / `5` | Local clustering iterations / restarts |
| `--param prox_builder` | `nearest_top_m0` | Traversal Graph construction variant |
| `--k` | `10` | Number of returned multi-vectors |
| `--param ef_nav_query` | `128` | Routing Graph search beam width (`efR` in the paper) |
| `--param ef_search` | `k` | Traversal Graph search beam width (`efS` in the paper) |
| `--param rerank_amp` | `0` | Exact MaxSim reranking amplification; `0` disables reranking |

Use `ef_search >= k > 0`. To enable exact MaxSim reranking, set `rerank_amp >= 1`. The reranked candidate count is bounded by `ceil(rerank_amp * k)`, `ef_search`, and the number of candidates found. The example above uses `rerank_amp=2.64`, the value reported in the query-time ablation, as an example operating point. Increase or sweep `ef_search` to examine recall/latency trade-offs rather than assuming one setting reproduces every result.

The standard searcher requires a complete MNG index; it rejects the special `nav_only=1` construction mode.

### Output and evaluation

For `--output results/mng.json`, the searcher writes:

- `results/mng.json`: timing, configuration, and evaluation summaries.
- `results/mng.rankings.i32.bin`: ranked document row indices.
- `results/mng.rankings.scores.fp32.bin`: corresponding scores.
- `results/mng.rankings.meta.json`: ranking dimensions and metadata.

Map ranking row indices to original document IDs using the document bundle's `docids.i32.bin`. Search without `--gt` is supported, but the uncomputed evaluation fields in the JSON must not be interpreted as measured recall values.

Search is forced to one software thread by the runtime. For controlled latency measurements, optionally pin the process to one available logical CPU using `taskset -c CPU_ID`; select an allowed CPU with `taskset -pc $$` on Linux. Keep the same affinity and evaluation settings across methods.

### Build options

`config.mk` provides the shared build settings:

| Variable | Purpose |
| --- | --- |
| `CXX`, `CXXFLAGS`, `CPPFLAGS`, `LDFLAGS`, `LDLIBS` | Compiler and additional compile/link flags |
| `FAISS_ROOT`, `FAISS_LIB_DIR`, `FAISS_LIBS` | FAISS installation and link configuration |
| `MKL_ROOT`, `MKL_LIB_DIR`, `MKL_LIBS` | Intel MKL installation and link configuration |
| `MNG_BACKEND` | `auto`, `scalar`, `avx2`, or `avx512` |
| `MNG_INDEX_THREADS` | Main MNG construction threads; default `96` |

`MNG_BACKEND=auto` inspects the build machine's Linux CPU flags. If building for a different machine, select a backend supported by the execution CPU. The AVX-512 build uses AVX-512 F/DQ/VL and FMA; the AVX2 build uses AVX2 and FMA. The scalar setting affects MNG scoring kernels and does not remove the MKL/FAISS dependencies. The default MKL configuration links the GNU threading layer.

Make does not track changes to command-line variable values. After changing backend, threading, or library settings, rebuild the affected component:

```bash
make -C mng clean
make -C mng -j8 \
  FAISS_ROOT=/path/to/faiss MKL_ROOT=/path/to/mkl \
  MNG_BACKEND=avx2 MNG_INDEX_THREADS=16
```

The repository does not currently provide a locked dependency environment. The paper's recorded environment is listed [above](#environment); other compiler and dependency combinations require validation on the target machine.

The root `make` target also builds the C++ baselines and ablation programs. Use the `mng` target above to build MNG alone. To build the optional C++ bundle inspection tools:

```bash
make -j8 encoders
```

This creates `encoders-v2/build/mvbundle_inspect` and `encoders-v2/build/gt_inspect`.

## Compared algorithms and ablations

The repository includes C++ implementations or integrations for ColBERT, PLAID, DESSERT, WARP, IGP, MUVERA, and GEM, plus an XTR Python entry point and brute-force MaxSim search. Baseline setup is method-specific: XTR requires ScaNN, and the MUVERA graph builder requires a separately prepared FDE cache. Instructions for building and running the baselines are provided in [docs/reproduction.md](docs/reproduction.md#build-options-and-baselines). Detailed method descriptions and experimental configurations are in Appendix A of the [full paper](fullpaper.pdf).

The three `mng_*ablation` / `mng_build_maxsim_r95_search_quality` directories contain the query-time and construction-time MaxSim ablations. GEM is included for index construction comparison but excluded from the paper's search performance evaluation because construction remained incomplete after over 101 hours on the smallest dataset.
